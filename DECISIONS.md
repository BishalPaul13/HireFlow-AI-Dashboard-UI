# Hackathon Decisions: HireFlow AI

**1. Why this ingestion strategy over the obvious alternative you rejected?**
For resume and application ingestion, we opted for client-side text extraction (using lightweight libraries like pdf.js) and manual data entry rather than a heavy, server-side OCR pipeline (like AWS Textract or Google Document AI). While a dedicated backend OCR service is the "obvious" choice for parsing complex, uniquely formatted resumes with high accuracy, it introduces significant overhead for a 24-hour build: managing API keys, building file upload endpoints, handling server-side latency, and cloud costs. Client-side extraction kept the MVP fast, serverless, and easy to deploy, allowing the limited time to be spent on UI polish and core user flows.

**2. One trade-off you made under the time limit, and what you’d do with a real week.**
The biggest trade-off was mocking the dashboard data and AI insights instead of connecting to a live database and AI backend. To ensure a flawless pitch presentation within the time limit, I hardcoded the "Applications Tracked" stats, the "Resume Score" visualization, and the interview readiness indicators. If I had a real week, I would set up a proper backend (e.g., Supabase or Node/Express with PostgreSQL) to persist user profiles, and wire the Resume Analyzer to a live LLM API to provide dynamic, personalized feedback based on actual resume data.

**3. Where did you use AI tools, and what did you personally verify or change afterward?**
I heavily utilized AI coding assistants to generate the boilerplate React components, Tailwind CSS styling, and the initial `framer-motion` animations for the landing page. However, AI-generated UI often lacks nuance in spatial rhythm and theme consistency. After generating the base components, I manually intervened to refine the glassmorphism effects (adjusting opacities and borders), fixed color contrast issues to ensure a premium dark mode aesthetic, and thoroughly tested and fixed mobile responsiveness so elements stacked correctly. I also added and manually verified the easter egg (clicking the logo 5 times for confetti) to ensure the state logic worked as intended.
